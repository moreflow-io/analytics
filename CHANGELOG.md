# Changelog

All notable changes to `@moreflow/analytics` are documented in this file.

## Unreleased

## 0.1.1

- `setRoute(route, path?)`: the optional `path` binds the template to a navigation's target path, for a route reported before the URL changes. `useAnalyticsRoute()` now passes the target path from `onBeforeNavigate`, so a navigation's pageview carries the matched template even while route loaders still run (before, the template was bound to the old path and cleared by the push).
- `requestFlags()` in `@moreflow/analytics/tanstack-start/server` reads the platform's `x-mf-flags` header of the current request (null off the platform); pass it to `AnalyticsProvider` as `flags`.

## 0.1.0

- Link and image content slots: slot values stay strings; the site's `moreflow.slots.json` declares a slot as `text`, `link` or `image`, so a section such as `featured.title`, `featured.cta_url` and `featured.image` (plus `featured.image_alt` for its alt text) can be varied as a whole. `<ContentLink id href>` and `useContentLink(id, fallback)` render an assigned target only when it is a `/path` or an https URL (never `javascript:`, `data:` or `//host`) and add `rel="noopener"` to absolute ones; `<ContentImage id altId src alt>` and `useContentImage(id, fallback)` render https images only (moreflow publishes the media asset's served URL). `getContentLink`, `getContentImage`, `isSafeContentHref` and `isSafeContentImageSrc` are the framework-free helpers; `getContent` and `useContentSlot` are unchanged.
- Integration source and tracker version: every batch says how the tracker was loaded (`data-src`: `npm` from `init`, `npm/react` from `AnalyticsProvider` from `@moreflow/analytics/react`, `npm/tanstack-start` from `AnalyticsProvider` from `@moreflow/analytics/tanstack-start`, `injected` from the site platform, `tag` for a hand-placed script) and which tracker build it is: `<package version>+<hash of the tracker sources>`, so it changes with every tracker change. `analytics.properties.get` lists the installs of the last 24 hours under `liveness.integrations`.
- Route templates: `setRoute(route)` reports the template of the current page (`/blog/[slug]` for `/blog/my-post`), and the events of that page carry it, so reports group one page instead of every slug. `useAnalyticsRoute()` in `@moreflow/analytics/tanstack-start` reports the matched route on load and on every navigation; `routeTemplateOf(fullPath)` is the conversion from TanStack path syntax. `@tanstack/react-router` is an optional peer dependency of that subpath.
- Debug mode for installers: `init({ debug: true })` (and `AnalyticsProvider debug`) sets `data-debug="true"` on the tracker script, so the tracker logs each event to the console and names why a batch was refused. On `localhost`, `127.0.0.1`, `[::1]` and `*.local` debug is on without the option and the tracker sends nothing there. A failed tracker load is logged once in debug mode, and the anti-flicker is still released. Without debug nothing is written to the console.
- `beforeSend(hook)` (and `init({ beforeSend })`, `AnalyticsProvider beforeSend`): a site hook that sees each event before the tracker sends it and can change its URL or props, or drop it by returning `null`. A throwing hook drops the event. `BeforeSendHook` and `BeforeSendEvent` are exported types.
- TanStack Start helpers. `@moreflow/analytics/tanstack-start` is client-safe and imports no TanStack module: `variantsFromHeaders`, `contentFromHeaders` and `variantsMeta` turn the platform's `x-mf-variants` and `x-mf-content` headers into the values `AnalyticsProvider` and a route `head()` take. `@moreflow/analytics/tanstack-start/server` holds `requestVariants()` and `requestContent()`, which read the current request in a server function or server route; it imports `@tanstack/react-start/server`, an optional peer dependency needed only by that subpath. These helpers replace the TanStack Start glue of the removed `@moreflow/site-kit` package.
- Feature flags for customer sites: `isFeatureEnabled(key, flags?)` and `getFeatureFlagPayload(key)` read a site flag set in moreflow (rollout share, rules, contacts, JSON payload). The platform decision (`x-mf-flags` header through `AnalyticsProvider flags`, or `<meta name="mf-flags">`) wins for the keys it lists; other keys come from the tracker. `parseFlags`, `serializeFlags`, `readPlatformFlags` and `flagsHeaderName` handle the format. Flags record no exposure events and never write to storage.
- React: `useFeatureFlag(key, flags?)` and `useFeatureFlagPayload(key)`; `AnalyticsProvider` takes `flags`.
- Content experiments: `AnalyticsProvider` takes `content` (the parsed `x-mf-content` header); `useContentSlot(id, fallback)` and `<ContentSlot id>` render the assigned text as plain text, server and browser alike. `parseContent`, `serializeContent`, `contentHeaderName` and `getContent(slot, content)` handle the header; `getContent` returns null off the platform.
- Custom event properties: `track(name, props)` takes lower snake_case keys with string, number or boolean values (at most 25 per event; longer strings are cut to 255 characters). Values that look like an email address or a phone number are dropped by the ingest.
- `register(props)` and `unregister(key)` manage super properties, merged into every later event. They persist across visits only after `consent(true)`; without consent they stay in memory.
- `reset()` clears super properties and the contact, and with consent starts a new first-party visitor id (call it on logout).
- `useAnalytics()` also returns `register`, `unregister` and `reset`.
- `trackerConfigEvent` (`moreflow-analytics:config`): the tracker dispatches it once its experiment config arrived; the React bindings re-resolve on it so browser-side assignments and their exposure apply without a reload.
- Initial release: `init({ siteKey, src?, antiFlicker? })` loads the moreflow tracker once; `track`, `identify` and `consent` queue until it loads; `getVariant(key, variants?)` reads platform, tracker or `'control'` variants; `parseVariants` and `serializeVariants` handle the `exp=variant;…` format.
- React bindings at `@moreflow/analytics/react`: `AnalyticsProvider`, `useVariant`, `<Variant>` and `useAnalytics`, with hydration-safe variant reads.
